= Announcing `envsafe` for Agentic coding
:description: envsafe v0.2.0, a command-line tool and MCP server, lets AI agents and people edit .env files without secret values ever reaching chat, terminal output, or logs.
:revdate: 2026-11-02
:keywords: news, envsafe, dotenv, secrets, AI agents, MCP, release

envsafe v0.2.0 is out. It edits `.env` files for AI coding agents and the people who work alongside them, and it never prints a secret value. Values go in through standard input, an environment variable, or a file. What comes back is key names, line numbers, and exit codes.

The problem it addresses is ordinary. An agent is asked to rotate an API token. To find the right line, it runs `cat .env`. Every credential in the file is now in the chat transcript, the terminal scrollback, and whatever log the session ships to. A quick `sed` edit can do the same thing in reverse: the new token ends up in the command line, and shell history keeps it. The agent did nothing malicious. It used the only tools it had.

envsafe swaps those tools for commands that cannot leak:

[source,sh]
----
printf '%s' "$NEW_TOKEN" | envsafe set API_TOKEN --stdin --dry-run
envsafe list
envsafe validate --schema .env.example
----

The dry run shows what would change. Values appear as `<redacted>`, and each change is labeled _would add_ or _would update_. `set` is an upsert by default. `--only-existing` refuses to create a key that is not there, which catches typos. `--only-new` refuses to overwrite one that is. `list` prints only key names, unless asked for masked markers. `validate` reports syntax errors, duplicate keys, and required keys that are missing or empty, checked against a `.env.example` or a Markdown/AsciiDoc variable registry. The `set` command accepts no value on the command line at all.

The files stay as their authors wrote them. Comments, blank lines, section headers, quoting, `export` prefixes, and CRLF line endings all survive an edit byte for byte. Writes are atomic, and the tool never adds a byte-order mark. New in v0.2.0, the comment lines directly above a key now belong to that key. `set --comment` adds or replaces them. `unset` leaves them in place unless `--with-comment` is passed. New keys can go after a named key (`--after`) or at the end of a section (`--section "# == Mail =="`). envsafe refuses any comment that contains the value being set.

Also new in v0.2.0: `envsafe mcp` runs a Model Context Protocol server over stdio. It exposes `envsafe_set`, `envsafe_unset`, `envsafe_list`, and `envsafe_validate`. The set tool takes no inline value argument, because tool arguments pass through the model's context. It reads the value from an environment variable the server can see, or from a file.

== Install

Windows users can install the MSI from the link:https://github.com/dev-centr/envsafe/releases/tag/v0.2.0[v0.2.0 release], which puts `envsafe` on `PATH`. The same release has archives for Linux x64, Linux arm64, and macOS arm64, plus SHA-256 checksums.

To register the MCP server in Cursor (`.cursor/mcp.json`):

[source,json]
----
{ "mcpServers": { "envsafe": { "command": "envsafe", "args": ["mcp"] } } }
----

In Claude Code:

[source,sh]
----
claude mcp add envsafe -- envsafe mcp
----

Other MCP clients use the same stdio command, `envsafe mcp`.

envsafe is written in D, is MIT-licensed, and also ships as a library. Source, documentation, and the issue tracker are at link:https://github.com/dev-centr/envsafe[github.com/dev-centr/envsafe]. A `move` command and Windows arm64 builds are not in this release.
